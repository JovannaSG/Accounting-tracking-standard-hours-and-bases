# Учёт нормочасов (1С:Бухгалтерия · 1С:Фреш)

Внешнее веб-приложение (Streamlit) для нормированного учёта трудозатрат
аутсорсинговых бухгалтеров по фактическим операциям в 1С:Бухгалтерия.
Данные выгружаются через OData-сервис 1С:Фреш.

Описание последних доработок и известных ограничений — в
[CHANGELOG.md](CHANGELOG.md). Подробная инструкция — в
[docs/Руководство_администратора_и_пользователя.md](docs/Руководство_администратора_и_пользователя.md).

## Возможности

- Выгрузка документов за период через OData 1С:Фреш (блок «Банк и касса» +
  «Первичные документы», документы ТМЦ, варианты авансового отчёта),
  свыше 20 видов документов. Перечень видов можно сузить индивидуально
  для каждой базы («Базы и доступ» → «Виды документов этой базы»).
- Расчёт нормочасов: количество операций × норма × коэффициент сложности.
- Распределение по ответственным сотрудникам аутсорсера (ключ — ФИО; для
  технических имён 1С вида «Е_Кирищёнок» задаётся алиас `user_1c`);
  несопоставленные авторы попадают в «Не распределено».
- Отчёт с итогами по клиентам и сотрудникам; отчёт «Загрузка сотрудников»
  (доля от фонда ч/мес, по умолчанию 130 ч).
- Предупреждение о видах документов, для которых норма не задана, —
  они считаются с нормой 0; недостающие нормы можно завести прямо во
  вкладке «Нормы» («Новый вид документа»).
- Выгрузка в Excel: лист «Отчёт» (итоги по клиентам) + «Загрузка сотрудников»
  + «Сводка по клиентам». Кнопки «Скачать Excel» и «Очистить отчёт»
  расположены под таблицами отчёта.
- Вкладки: Отчёт / Диагностика OData / Нормы / Сотрудники / Базы и доступ /
  Пользователи.
- Роли доступа (администратор / руководитель / бухгалтер): руководитель правит
  нормы и сотрудников и видит все базы; бухгалтер видит только свои операции
  (привязка «пользователь → сотрудник») и разрешённые базы; пользователями и
  редактированием баз управляет только администратор.

## Технологии

Python 3.11+, Streamlit, pandas, requests, openpyxl, SQLite (WAL).

## Установка

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate   |  Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка (переменные окружения)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AUDIT_DB_PATH` | Путь к SQLite-БД приложения | `norm_hours.db` |
| `AUDIT_USERS_CONFIG` | Путь к `users.json` (роли + доступы к базам) | `users.json` |
| `AUDIT_USERS` | Fallback-пользователи `логин:хэш,логин2:хэш2` (PBKDF2) | пусто (выкл.) |
| `AUDIT_DB_SECRET_KEY` | Ключ шифрования паролей клиентских баз (Fernet, base64 32 байта) | пусто (пароли в открытом виде) |
| `UI_HOST` / `UI_PORT` | Адрес/порт Streamlit | `127.0.0.1` / `8503` |
| `UI_IDLE_TIMEOUT_MIN` | Таймаут бездействия сессии, мин (0 — не завершать) | `30` |

Авторизация: скопировать `users.example.json` → `users.json`, сгенерировать
хэши командами:

```bash
python -m core.auth hash <пароль>
```

Если `users.json`/`AUDIT_USERS` не заданы — аутентификация отключена.
Для совместимости при отсутствии `users.json` принимается и `user.json`
(одноимённый файл с опечаткой в названии).

Защита входа: после 5 неудачных попыток вход блокируется на 5 минут
(`core.auth.MAX_LOGIN_ATTEMPTS` / `LOCKOUT_SECONDS`), пароль должен быть
не короче 8 символов.

Шифрование паролей баз: сгенерируйте ключ и задайте `AUDIT_DB_SECRET_KEY`:

```bash
python -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

Пароли, сохранённые до включения ключа, читаются как есть и перешифровываются
при первом сохранении. **Ключ нужно хранить отдельно от БД** — при его утере
пароли баз восстановить нельзя (потребуется заново внести их в «Базы и доступ»).

## Запуск

```bash
python app/run.py
```

Открыть в браузере: http://127.0.0.1:8503

## Запуск в Docker

```bash
docker compose up -d --build
```

Открыть в браузере: http://localhost:8503

Рабочие данные (SQLite-БД и `users.json`) хранятся в docker-томе
`norm-hours-data` (каталог `/data`). Внешний порт и переменные окружения —
в `docker-compose.yml`.

Несколько экземпляров на одной виртуальной машине: у каждого свой внешний
порт (`8503:8503`, `8504:8503`, …), своё имя контейнера (`container_name`)
и свой том — измените эти три значения в `docker-compose.yml` либо запускайте
через `docker compose -p <имя> up -d`.

Подробности по учётным записям, ролям, настройке баз/норм/сотрудников и
эксплуатации — в [руководстве администратора и пользователя](docs/Руководство_администратора_и_пользователя.md).

## Замечания по OData

- «Журнал операций» (`DocumentJournal_*`) в составе OData базы 1С:Фреш,
  как правило, не публикуется, поэтому выгрузка ведётся по каждой сущности
  документа отдельно (см. `core/doc_types.json`).
- Ответственный документа — поле `Ответственный_Key`; ФИО расшифровываются
  локально через справочник «Пользователи» (клиентский JOIN: GUID → имя).
- Фильтр по дате кодируется как `Date ge datetime'..' and Date le datetime'..'`
  с полным временем границ (в 1С OData голая дата трактуется как 00:00:00).

## Ограничения MVP

- Нормы зафиксированы для MVP (блоки «Банк и касса» и «Первичные документы»).
- СНО клиента заполняется вручную (соответствующий регистр в OData-составе
  обычно не публикуется).
- Для каждой базы 1С:Фреш требуется отдельная запись в разделе «Базы и доступ»
  с логином/паролем OData-пользователя и ролью «УдаленныйДоступOData».
- Норма подбирается по наименованию вида документа; если на одно
  наименование заведено несколько норм (например, с разной СНО), в расчёт
  попадёт первая — разделять такие нормы нужно уникальными наименованиями.
