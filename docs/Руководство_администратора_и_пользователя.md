# Руководство администратора и пользователя

Система «Учёт нормочасов» — веб-приложение (Streamlit) для нормированного
учёта трудозатрат аутсорсинговых бухгалтеров. Данные выгружаются из
продуктивных баз 1С:Бухгалтерия через OData-сервис 1С:Фреш, операции
оцениваются по нормам, результат показывается в отчёте и выгружается в Excel.

Основные понятия:

- **База 1С:Фреш (клиент)** — одна продуктивная база, соответствует одному
  клиенту аутсорсера. Для каждой базы создаётся запись во вкладке «Базы и
  доступ» с реквизитами OData-пользователя.
- **Норма** — трудозатраты на одну операцию вида документа (в минутах) плюс
  коэффициент сложности. Нормочасы = операций × минут/60 × коэффициент.
- **Сотрудник** — бухгалтер аутсорсера. Записывается по полному ФИО; у него
  может быть алиас (техническое имя пользователя в 1С вида `Е_Кирищёнок`).
- **Пользователь системы** — учётная запись для входа в приложение.
  Бухгалтеру привязывается сотрудник, управляющий или администратор — нет.

---

## 1. Роли и права доступа

Права задаются ролью пользователя (поле «Роль» в учётной записи):

| Раздел приложения | Администратор | Руководитель | Бухгалтер |
|---|---|---|---|
| Отчёт (формирование, Excel) | полностью | полностью | только свои операции |
| Диагностика OData | да | да | да |
| Нормы трудозатрат | редактирование | редактирование | нет |
| Сотрудники | редактирование | редактирование | нет |
| Базы и доступ | редактирование | просмотр | просмотр |
| Пользователи | редактирование | нет | нет |

Пояснения:

- **Администратор** видит все базы и все операции, управляет учётными
  записями, базами, нормами и сотрудниками.
- **Руководитель** видит все базы, все операции и отчёты; правит нормы и
  сотрудников; учётные записи и базы — только просмотр.
- **Бухгалтер** видит только **свои** операции (по сотруднику, привязанному к
  его учётной записи) и только те базы, которые указаны у него в «Доступных
  базах». Блок «Не распределены» бухгалтеру не показывается.

Вкладки, недоступные роли, не отображаются в меню приложения.

## 2. Установка и запуск

### 2.1 Локально (разработка)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate | Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app/run.py
```

Открыть в браузере: **http://127.0.0.1:8503** (порт задаётся переменной
`UI_PORT`).

### 2.2 Docker (production)

```bash
docker compose up -d --build
```

Открыть в браузере: **http://localhost:8503** (левую часть проброса можно
поменять в `docker-compose.yml`, например `"8504:8503"`).

Если на одной виртуальной машине несколько экземпляров приложения, у каждого
должны быть свои: внешний порт, имя контейнера (`container_name`) и том.
Измените эти три значения в `docker-compose.yml` либо запускайте экземпляры
через `docker compose -p <имя> up -d` — тогда имена и том получат префикс
проекта.

Рабочие данные живут в docker-томе `norm-hours-data` (смонтирован в `/data`):

- `/data/norm_hours.db` — SQLite-БД приложения (пользователи, базы, нормы,
  сотрудники);
- `/data/users.json` — конфиг пользователей; он **не** создаётся автоматически,
  положите его в том командой из раздела 3.1.

Полезные команды:

```bash
docker compose logs -f          # журнал
docker compose restart          # перезапуск
docker compose down             # остановка (данные в томе сохраняются)
```

**Бэкап** данных — это копия тома `norm-hours-data`. Остановите контейнер,
затем:

```bash
docker compose stop
docker run --rm -v norm-hours-data:/data -v %cd%:/backup \
  alpine tar czf /backup/norm-hours-data.tar.gz -C /data .
docker compose up -d
```

(В PowerShell вместо `%cd%` используйте `${PWD}`.)

Чтобы обновить `users.json` внутри тома без остановки контейнера:

```bash
docker cp users.json norm-hours:/data/users.json
docker compose restart norm-hours
```

### 2.3 Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AUDIT_DB_PATH` | путь к SQLite-БД приложения | `norm_hours.db` |
| `AUDIT_USERS_CONFIG` | путь к конфигу пользователей `users.json` | `users.json` |
| `AUDIT_USERS` | fallback-пользователи `логин:хэш,логин2:хэш2` (PBKDF2) | пусто (выкл.) |
| `UI_HOST` | адрес для Streamlit | `127.0.0.1` |
| `UI_PORT` | порт Streamlit | `8503` |

## 3. Настройка для администратора

### 3.1 Первый запуск и создание учётных записей

Аутентификация включается автоматически, когда в системе появляется хотя бы
одна учётная запись. Первая запись создаётся из файла `users.json`
(seed-механизм работает только когда таблица пользователей пуста).

1. Скопируйте шаблон и укажите пароль администратора:

   ```bash
   cp users.example.json users.json      # локально
   # в Docker: cp образу->том не нужен: правите /data/users.json внутри тома
   ```

   Формат файла:

   ```json
   {
     "admin": { "role": "admin", "password": "<пароль>" },
     "buhgalter": {
       "role": "accountant",
       "allowed_urls": ["https://msk1.1cfresh.com/a/ea/1119958"]
     }
   }
   ```

   Значение `password` — это PBKDF2-хэш, а **не пароль в открытом виде**
   (открытый текст при входе не принимается). Сгенерировать:

   ```bash
   python -m core.auth hash <пароль>
   ```

   Seed выполняется **один раз**, только когда таблица пользователей пуста.
   После первого запуска пользователи живут в БД (вкладка «Пользователи»),
   и правка файла `users.json` на них не влияет — управляйте ими в интерфейсе.

2. Запустите приложение и войдите под `admin`.
3. Первым делом смените пароль администратора: вкладка **«Пользователи»** →
   выберите себя → «Новый пароль» → «Сохранить».
4. Остальные пользователи создаются там же во вкладке «Пользователи» (см. 3.2).

Учётную запись можно задать и через переменную `AUDIT_USERS`
(`логин:хэш,логин2:хэш2`) — она действует как fallback, если записи нет в БД.

**Защита входа.** После 5 неудачных попыток входа логин блокируется на
5 минут (счётчик попыток в памяти процесса — после перезапуска контейнера
обнуляется). Пароль, задаваемый в интерфейсе, должен быть не короче
8 символов. Сессия завершается автоматически, если пользователь не нажимал
ничего 30 минут; таймаут настраивается переменной `UI_IDLE_TIMEOUT_MIN`
(`0` — не завершать).

### 3.2 Вкладка «Пользователи» (только администратор)

Добавление:

- **Логин** — имя для входа (сравнение регистронезависимое);
- **Роль** — Администратор / Руководитель / Бухгалтер;
- **Пароль** (дважды, не короче 8 символов; флажок «Показать пароль»
  открывает оба поля);
- **Доступные базы** — URL баз 1С:Фреш, по одному на строку. Поле влияет
  только на бухгалтера: он видит строго эти базы. У руководителя оно
  информативное — руководитель видит все базы;
- **Сотрудник** — привязка бухгалтера к сотруднику (его операции и только их
  он видит в отчёте; привязка видна только для роли «Бухгалтер»).

Над формами выводится таблица всех пользователей: логин, роль (русскими
словами), признак активности, привязанный сотрудник и список доступных баз.

Редактирование: выбор пользователя → форма с ролью, активностью, сменой
пароля, списком баз и привязкой сотрудника. Пустой пароль означает
«оставить прежний».

Удаление: выбор пользователя из списка → подтвердить флажком.

Защита: нельзя разжаловать или удалить **последнего** действующего
администратора; нельзя удалить собственную учётную запись.

### 3.3 Вкладка «Базы и доступ»

Добавьте по одной записи на каждую базу 1С:Фреш (один клиент = одна база):

- **Название** — клиент;
- **URL OData** — адрес публикации, например
  `https://msk1.1cfresh.com/a/ea/1119958`;
- **Логин/пароль** — OData-пользователя базы (роль
  «УдаленныйДоступOData» в 1С:Фреш);
- **СНО** — система налогообложения клиента (заполняется вручную);
- **Группа** — необязательная группировка клиентов.

Пароли клиентских баз можно зашифровать. Сгенерируйте ключ и задайте
переменную окружения `AUDIT_DB_SECRET_KEY`:

```bash
python -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

После этого новые и изменённые пароли сохраняются в шифрованном виде
(префикс `enc:v1:`), а ранее сохранённые открытыми — читаются как есть и
перешифровываются при первом изменении. **Храните ключ отдельно от БД**:
при его утере пароли баз восстановить нельзя, их придётся ввести заново.
Если ключ не задан, поведение прежнее — пароли лежат в открытом виде.

Администратор и руководитель видят все базы; бухгалтер — только указанные у
него в «Доступных базах». Для manager/accountant вкладка работает в режиме
просмотра.

### 3.4 Вкладка «Нормы»

- Кнопка **«Засеять нормы по умолчанию»** добавляет нормы по всем видам
  документов из реестра (для новых действий не затирает уже существующие
  нормы).
- Редактирование: выберите вид документа из списка (название + ключ) и
  измените норму в минутах, коэффициент сложности, СНО, комментарий или
  признак «Норма активна». Выключенная норма не участвует в расчёте.
- Добавление **новых** видов документов требует правки реестра
  `doc_types.json` — интерфейс правит только существующие записи.

### 3.5 Вкладка «Сотрудники»

- **ФИО (ключ)** — как минимум это имя должно полностью совпадать с именем
  автора документа в 1С (иначе автор попадёт в «Не распределено»);
- **Пользователь 1С (алиас, опц.)** — техническое имя вида `Е_Кирищёнок`;
- **Роль сотрудника**, **Фонд часов в месяц** (по умолчанию 130) — для отчёта
  «Загрузка сотрудников»;
- **Массовый импорт по ФИО** — вставьте список имён по одному на строку;
- Удаление — через выбор в списке.

## 4. Работа пользователя

### 4.1 Сайдбар (общие элементы)

- **База 1С:Фреш** — выбор клиентской базы (список зависит от роли);
- **Период** — месяц / квартал / год / произвольные даты;
- **Блок операций** — категории документов: ровно три — «Банк и касса»,
  «Первичные документы», «ТМЦ и ОС»;
- **Вариант отчёта** — готовые наборы группировок (ТЗ §9.3): по клиенту,
  по сотруднику, по видам документов, по клиентам за месяц, по видам
  операций, «Операции без ответственного». Вариант «Пользовательская»
  оставляет выбор группировок вручную. Смена варианта не требует повторной
  выгрузки из 1С — используется уже загруженный кэш;
- **Группировка** — по клиенту, сотруднику, виду документа и операции;
- кнопка **«Сформировать отчёт»**;
- после формирования — элементы отборов, **сортировка** и «Выгрузка Excel».

Если базы не настроены, в сайдбаре предлагается ввести URL/логин/пароль
OData однократно («без сохранения») для разовой проверки.

Под таблицей отчёта в сайдбаре появляется строка **«Применяются отборы:
…»** — она перечисляет активные фильтры, чтобы не забыть о них.

**Сортировка** (ТЗ §9.2) по умолчанию: клиент ↑, вид документа ↑,
количество операций ↓, трудозатраты ↓. Сортировку можно изменить в
сайдбаре (колонка и направление); она действует только на экран — в Excel
выгружается сортировка по умолчанию, чтобы подытоги по клиентам не
разрывались.

### 4.2 Вкладка «Отчёт»

1. Выберите базу, период, блоки и группировку; нажмите «Сформировать отчёт».
   Данные выгружаются из 1С:Фреш за период и кэшируются в текущей сессии.
2. После формирования появляются итоги (операций, нормочасов) и таблица
   отчёта. Если сменить базу или период, кэш сбрасывается автоматически.
3. Под таблицей — фильтры по колонкам отчёта (после формирования) и блок
   **«Загрузка сотрудников»** (операции, часы и доля от фонда по каждому
   сотруднику).
4. Блок **«Не распределены»** — авторы, для которых нет сотрудника с таким
   ФИО/алиасом. Администратор должен добавить их во вкладке «Сотрудники».
   Бухгалтерам блок не показывается.
5. У варианта «Отклонение от нормы» выводится предупреждение: учёт
   фактического времени не подключён (очередь II), сравнение нормы и факта
   пока недоступно.

### 4.3 Выгрузка в Excel

Кнопка **«Скачать Excel (.xlsx)»** в сайдбаре формирует файл из трёх листов:

1. **Отчёт** — данные как на экране: итоги по каждому клиенту и общий итог;
2. **Загрузка сотрудников** — часы и доля загрузки по сотрудникам;
3. **Сводка по клиентам** — клиент, ИНН, количество операций, нормочасы,
   доля от общего итога (%).

Если часть видов документов не удалось выгрузить (например, сущность не
опубликована), это показывается в отчёте отдельным блоком
«Виды документов, которые не удалось загрузить» (бухгалтеру не виден).

Имя файла: `normirovanie_<период>.xlsx`.

### 4.4 Вкладка «Диагностика OData»

Кнопка **«Проверить состав публикации»** читает `$metadata` выбранной базы и
показывает, какие сущности видов документов опубликованы (Да/НЕТ). Если
документ не выгружается — в первую очередь смотрите сюда, затем во вкладку
«Нормы» (ключи видов документов).

## 5. Частые вопросы

**Форма входа не появляется.** В системе нет ни одной учётной записи —
аутентификация отключена. Создайте первую запись в `users.json` (см. 3.1)
и перезапустите приложение.

**Забыт пароль администратора.** Остановите приложение и очистите таблицу
пользователей, затем перезапустите — приложение создаст записи заново из
`users.json`:

```bash
# локально
python -c "from core import db; db.init_db(); import sqlite3, os; p=db._DB_PATH; c=sqlite3.connect(p); c.execute('DELETE FROM users'); c.commit(); c.close()"
# Docker
docker compose exec norm-hours python -c "from core import db; import sqlite3; c=sqlite3.connect(db._DB_PATH); c.execute('DELETE FROM users'); c.commit(); c.close()"
```

После чего задайте новый пароль в `users.json` и перезапустите.

**«Порт занят».** Приложение уже запущено (проверка в `app/run.py`).
Остановите старый экземпляр и повторите запуск.

**Документы не выгружаются.** Проверьте «Диагностика OData»: сущность может
не публиковаться в составе. Отдельно проверьте, что у OData-пользователя базы
есть роль «УдаленныйДоступOData».

**Операции «не распределены».** Добавьте сотрудника с ФИО, совпадающим с
именем автора в 1С (или укажите алиас `user_1c`) во вкладке «Сотрудники».

**Бухгалтер не видит свои операции.** Убедитесь, что в его учётной записи
выбрана роль «Бухгалтер», привязан сотрудник и в «Доступных базах» указаны
нужные URL.

**У бухгалтера пустой список баз.** В «Доступных базах» его учётной записи
перечислены URL баз; они должны совпадать с полем `url` записей во вкладке
«Базы и доступ».

**Вход заблокирован после нескольких неудачных попыток.** Сработала защита
от перебора: 5 попыток → блокировка на 5 минут. Подождите (или перезапустите
контейнер — счётчик попыток хранится в памяти процесса).

**Пароль от базы не подставляется после включения `AUDIT_DB_SECRET_KEY`.**
Значит, база была сохранена с другим ключом (или ключ утерян). Внесите
пароль заново во вкладке «Базы и доступ» — он сразу сохранится с текущим
ключом.

**Сессия завершилась сама.** Истёк таймаут бездействия
(`UI_IDLE_TIMEOUT_MIN`, по умолчанию 30 минут). Войдите заново; чтобы
отключить, задайте `0`.

## 6. Структура данных

- `users` (БД): login, роль, хэш пароля (PBKDF2-HMAC-SHA256), список URL баз,
  флаг активности, привязка к сотруднику (ФИО).
- `bases`: клиентская база (название, URL, логин/пароль OData, СНО, группа).
  Пароль шифруется Fernet, если задан `AUDIT_DB_SECRET_KEY`
  (префикс `enc:v1:`), иначе хранится как есть.
- `norms`: норма на операцию (doc_type, категория, минуты/часы, коэффициент,
  СНО, комментарий, флаг активности).
- `employees`: сотрудник (ФИО — ключ, алиас `user_1c`, роль, фонд часов).
- Пароли пользователей в открытом виде нигде не хранятся, только
  PBKDF2-хэши.
